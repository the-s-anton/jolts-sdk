# Local publisher setup agent

MCP package for a coding agent running on the publisher's
computer. Requires Node 22 or newer and a Git project. This is separate from the
publisher SDK and adds no dependency to the publisher's application.

Use the MCP configuration supplied by your app's Setup page. It runs
`npx --yes --package @jolts/agent@0.1.0 jolts-agent` with your absolute
project path and the app's generated authorization URL. Keep this local process
running while you approve and finish setup.

For source development, build from the repository root with `npm run agent:build`.
Configure the MCP client to run `node` with these arguments:
1. Absolute path to `packages/agent/dist/server.js`.
2. Absolute path to the publisher project.
3. Full authorization URL generated by Rails for the selected app.

No API paths are constructed by the agent. HTTPS is required except for local
development hosts.

Call `begin_publisher_setup`, open its approval URL for the publisher, then call
`finish_publisher_setup` after approval. The private RSA key stays in this process.
Rails returns an encrypted test credential after workspace approval. The process
decrypts it and installs `JOLTS_API_KEY` and `JOLTS_ENDPOINT` in `.env.local` with
owner-only permissions. Tool results never contain the credential.

The file must be ignored and untracked by Git. Initial setup never overwrites existing Jolts settings. Do not read the environment file into the agent's conversation.
Restarting this process before installation requires a new approval.

This package currently installs test credentials only. A successful installation
does not prove ad delivery, viewability, human traffic or earnings. Follow the
app's Setup instructions to install the SDK and verify a test ad.

Public CI tests the setup protocol, encrypted credential exchange, environment
file protection and packed executable. The private platform's browser suite
additionally tests the real approval UI, connection replacement, publisher
rendering and dashboard measurement against public npm versions.

## Replace a connection

Call `replace_publisher_connection` in the same configured project, approve in the
browser, then call `finish_publisher_setup`. The agent identifies the installed
credential by its digest and never includes its value in tool output. It replaces
only the expected key in the ignored, untracked environment file, preserving
unrelated variables. Replacement uses an owner-only temporary file inside Git
metadata and an atomic rename; cross-filesystem failures preserve the old file.

Only after the file is installed does the agent acknowledge with the new credential.
The old credential then expires within 24 hours, or at its existing expiry if sooner.
Restart or redeploy the publisher app to load the new environment during this overlap.
Revocation remains immediate. An acknowledgement retry does not rewrite the file or
extend the overlap. If the agent process stops before acknowledgement, the old
connection is not shortened; resume or start another approved setup, and revoke
unused connections from the dashboard. Installation acknowledgement does not prove
that a running publisher process has reloaded its environment.
