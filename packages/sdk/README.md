# Publisher SDK

Framework-independent server requests and browser rendering/measurement. There
are no runtime dependencies, remote scripts, cookies or automatic chat-history
interception. This version supports the test card only. This phase is
publisher-only: advertiser auctions and payments are not included.

## Install

```sh
npm install --save-exact @jolts/sdk@0.1.0
```

Use your app's Setup instructions to connect through the local MCP agent.
Approve the connection in your browser; the agent installs the server credential
without copying it into a chat. Never put that credential in browser code.
See the server and browser examples below for the integration contract.

## Local example

See [the local publisher example](examples/README.md). It uses synthetic content
and credentials installed by the MCP agent; there is no manual key-copy step.
The example requires a running Jolts platform and a publisher workspace.
It is not an authenticated production backend.

## Server

Import only the server entry point in backend code. Configure the complete API
endpoint supplied by setup and load the credential from the server's secret store.
Never include either the credential or the client object in frontend props.

```typescript
import { createClient } from "@jolts/sdk/server";

const client = createClient({
  endpoint: process.env.JOLTS_ENDPOINT!,
  apiKey: process.env.JOLTS_API_KEY!,
});

// Run after the host has produced its answer. Do not await this before sending
// the answer. These values come from your own authorized conversation/session.
const delivery = await client.requestAd({
  opportunity_id: answer.id,
  answer_id: answer.id,
  completed_at: answer.completedAt,
  origin: configuredPublicOrigin,
  context: { messages: permittedMessages },
  privacy: permissions,
});
```

Return only `delivery` (or JSON `null`) from your own authenticated backend route.
Set that response to `Cache-Control: no-store`; authorize the conversation and
apply your normal request limits. Do not proxy arbitrary browser-supplied context,
identity or consent to the ad API. Use your framework's trusted client-IP handling,
not the first value in an arbitrary `X-Forwarded-For` header.

Keep an opportunity ID and its body stable when retrying. The SDK does not retry
ad requests automatically. It aborts after 1.5 seconds by default and returns null
for timeout, network failure, invalid responses, no-fill and expiry. Set
`timeoutMs` explicitly if needed; a caller `AbortSignal` can also cancel the call.
Optional `onError` receives only a code and optional HTTP status, never request
content, credentials or provider error bodies. Redirects are refused so the key
cannot be forwarded to a different endpoint.

The transport accepts explicit messages, summary or keywords, plus the API's
optional pseudonymous user and client fields. It does not classify, geolocate or
generate user IDs. Server-side audience classification, risk checks and policy
enforcement are separate platform work; successful measurement is not proof of
human attention or payable revenue.

## Browser

```typescript
import { mountAd } from "@jolts/sdk/browser";

// publisherEndpoint is your backend URL, generated by your application's router.
const dispose = mountAd(container, publisherEndpoint, { className: "your-native-card" });
// Call dispose() when the answer/component unmounts.
```

`mountAd` returns cleanup immediately. Cleanup aborts an in-flight request, removes
the card and disconnects measurement. Mounting again in the same container
cancels the previous request; a late response cannot overwrite the new answer.
In a component framework, return this cleanup from the component effect.
Use a dedicated container per completed answer.

For custom loading, `loadAd` and `renderAd` remain available separately; cancel
your request and dispose your render when its answer unmounts. Browser diagnostics
distinguish cancellation, timeout, network failure and malformed responses.

The optional renderer creates semantic elements with textContent, a visible
sponsored label, and a safe link. It inherits the publisher's typography and
classes; it does not inject CSS or replace the host design system. An empty
response produces no card. Repeated mounting replaces the old card and cleans up
its observers. A new window uses `sponsored noopener noreferrer`.

For an existing native component, use `observeAd(element, delivery)` instead of
`renderAd`. Observe the entire card. Call its `recordClick(event)` only from the
advertiser link's trusted click handler; call `dispose()` on unmount. Pass
`onExpire` to remove your own component when its delivery expires. Always show
the supplied disclosure and sponsor, and preserve the complete action URL.

Measurement uses IntersectionObserver and Page Visibility. The continuous timer
resets when the card falls below the server-provided threshold or the tab becomes
hidden. Where supported, IntersectionObserver visibility tracking also detects
occlusion. Older implementations cannot prove complete absence of occlusion;
these are measurement signals, not human verification.

Receipts are sent with no cookies or referrer, and use stable event IDs. Network
and server failures get one bounded retry with the same receipt; other HTTP errors
are reported without retry. This never delays navigation. Synthetic `.click()`
does not produce a click receipt. Server deduplication remains authoritative.

Use `loadAd` to subtract the publisher round trip from the remaining lifetime.
The SDK uses a monotonic deadline, also capped by the absolute expiry. Directly
passing a serialized delivery to a custom component relies on the local wall
clock for transit age; it must not be cached or reused across page loads.

## Build and verify in this repository

From the repository root:

```sh
npm run sdk:test
npm pack ./packages/sdk --pack-destination ./tmp
```

The tarball contains only compiled entry points, declarations, this README, the manifest and MIT license.
There are no install scripts. `examples/server.mjs` is a separate local publisher
process with synthetic content; it receives its key through the environment and
does not expose it in HTML. The private platform browser regression starts it automatically,
checks real API and browser receipts, then stops it. The example is not an
authenticated production publisher backend.


Optional request signals include publisher-scoped user/session IDs, a declared
`user.actor` (`human`, `agent`, or `unknown`), and permitted end-user
`device.ip`, `user_agent`, `country`, `region`, and `language`. Never substitute
the backend server IP or automatically trust arbitrary forwarding headers.
`privacy.audience_insights` defaults to false and is separate from measurement;
the publisher app must also allow analysis. These fields are signals, not proof
of a human, consent or a payable impression. Do not infer permission from the
presence of an IP address or a user ID.
